## 裁决 1:支付密码只保护「余额划转」

**项目方原话**
> 「联系人只是方便快速填写表,不是因为是联系人就可以绕过支付密码的验证。」
> 范围:仅余额划转。

### 落地要求

- 验密点**只有一处**:划转的**执行**入口。不是"进入划转页",不是"选中联系人",
  是真正要动钱的那一次提交。
- **联系人不构成任何豁免。** 选中联系人只做一件事:把收款人字段填好。
  实现上禁止出现任何形如 `if isContact { skipPayPassword }` 的分支。
  这一条要有一条**行为级回归测试**钉死:"对联系人发起划转,不带支付密码 → 必须被拒",
  并做回滚验证(把豁免加回去,测试必须变红)。
- 提现、充值、兑换码等其他资金路径**本轮不接入**支付密码。
  提现是另一条出钱路径,不接入是本轮的**已知缺口**,要在文档里如实写出来,
  不要用"已保护资金操作"这种话糊过去。

### 安全底线(不可协商)

- 慢哈希存储(bcrypt/argon2),绝不明文、绝不快哈希(MD5/SHA 系一律不行)。
- 比对恒定时间;"未设置密码"/"密码错误"/"已锁定"的响应不得泄露账号状态差异
  给非本人调用者(本接口本来就要求登录态,所以主要防的是**响应时间**差异)。
- 验密接口挂 `middleware.CriticalRateLimit()`。
- 错误计数必须防并发绕过:同一账号并发打 N 个请求不能只算 1 次。
  扩展库是 MySQL,用行锁或原子自增,**不能读-改-写**。
- 锁定阈值与时长可配置(见裁决 5),管理员可提前解除、可重置用户支付密码,
  **这两个动作都必须写 `qianye/service/audit` 审计**。
- 邮箱找回:未绑定邮箱时提示先去绑定,**不要在这条路径上代为绑定** ——
  那等于给了一条绕过原邮箱的改绑路径。

## 裁决 2:违规影子模式 = 不扣费、不封号、**不计违规次数**,只留日志

**项目方原话**
> 「不扣费,不封号,不记录违规次数,存入日志,请求上下文,供管理员核查」

### 落地要求

- 影子命中的记录**必须与真实违规记录物理隔离**(另起一张表或另一个明确的作用域),
  绝不能混进驱动"违规次数 → 自动封号阈值"的那张表。
  混进去会让影子模式把用户推过封号线 —— 那正好是"不会真实执行"的反面。
- 影子记录要带**请求上下文**供管理员核查。至少:命中的规则、命中的文本片段
  (按现有脱敏口径截断)、模型、分组、令牌、时间、**若真实执行会扣多少钱**。
  最后一项是影子模式的全部价值 —— 没有它,管理员无法判断该不该转正式模式。
- 粒度:**每条规则一个模式**(shadow / enforce)。全局开关保留为总闸,
  总闸关掉时所有规则都不生效(含影子)。
- **迁移**:现存规则升级后一律保持**当前行为**(即 enforce),不要默认改成 shadow ——
  静默把生产风控降级成"只记录"是资损。新建规则的默认值可以是 shadow。
  这条与"默认 shadow 更安全"的直觉相反,理由是:对**已经在跑**的规则,
  改变行为才是风险,保持行为才是安全。

## 裁决 3:提现凭证图片存本地磁盘 + 鉴权下载

**项目方选择**:本地磁盘 + 鉴权下载接口。

### 落地要求

- 存 `data/` 下的独立目录(与配置文件同级,已在 `.gitignore` 内),**不是数据库**。
- 文件名**服务端生成**(随机 + 扩展名白名单),绝不用用户提供的文件名落盘,
  也不把用户文件名拼进路径。
- 类型白名单(仅 jpeg/png/webp)+ 大小上限 + **按魔数校验而非扩展名**。
- 落盘目录不得在任何静态资源路由的可达范围内。
- 下载走**鉴权接口**:仅本人与管理员可取。收款凭证属于 PII,
  与现有 `payeeAccount` 的加密/脱敏/保留期口径对齐。
- 单据被拒绝/撤销/超出保留期后,图片要随之清理 —— 与 `pii_retention_days` 同一套。
- 多节点部署时本地磁盘各存各的,这是**已知限制**,要在文档与配置注释里写明
  (单节点部署无碍;多节点需要共享存储或后续接对象存储)。

## 裁决 4:「移除调色板」仅限 Steins Gate 主题

**项目方选择**:仅 Steins Gate 主题下隐藏。

### 落地要求

- 选中 `steins-gate` 时,调色板抽屉只保留**亮/暗切换**,
  其余四个轴(font / radius / scale / contentLayout)隐藏。
- 换回其他预设时,五个轴照常可用 —— **不得影响任何其他预设**。
- 站点主题管理页(`/qy/admin/site-theme`)保留,它管的是"站点默认预设"这件事,
  与调色板是两回事。
- 前两版为"调色板可调"做的 `color-mix` 派生**保留**:昼夜切换本身就靠它,
  退回硬编码只会让昼夜两套值各写一遍。

## 裁决 5:哪些配置进 `qy_settings`(管理端可改),哪些留 YAML

需求 3 的「管理员不可以配置门槛」是本条的由来。划线原则沿用 commission 模块
(`qianye/modules/commission/api_admin.go` 的 `editableKeys`):

- **运营参数进 `qy_settings`**,管理端在线可改,每次改动写审计:
  划转门槛/单笔上限/日额度/日次数/冷却、支付密码的错误次数阈值与锁定时长。
- **安全开关与结构性配置留 YAML**,只能改文件后重载:
  功能总开关、跨库两阶段、限流、密钥、保留期。

理由:前者是运营每天要动的,让它必须改文件+重启不现实;后者动一次影响面很大,
需要一次显式的发布动作。

## 需求 4 的边界:只删管理端可用率,用户端必须保留

项目方在**更早的一轮**明确要求过「可用率监控是给用户全体查看的」。
本轮的「管理员的可用率监控没用,移除掉」指的是管理端那个页面。

**绝不能删**:采样 hook、聚合、清理等后台任务,以及用户端页面与其接口 ——
它们是同一套数据的生产者与另一个消费者。
删除时要一并清掉悬空的 i18n 键、query-key、路由与导航项,不留零消费方的残留。

## 通用约束(与前几轮相同)

- 金额换算只能用 `common.QuotaFromFloat` / `QuotaRound` / `QuotaFromDecimal`,禁裸 `int()` 转换
- 浮点绝不参与佣金/扣费(用 `shopspring/decimal`)
- JSON 走 `common.Marshal` / `Unmarshal`
- 跨库写主库前校验 `0 < amt <= common.MaxQuota`
- 所有 GORM 调用 `WithContext(ctx)`(`qianye/ctx_guard_test.go` 会检查)
- 请求参数解析走 `qianye/httpq`(`qianye/httpq_guard_test.go` 会检查)
- 分组名归一走 `qianye/groupname`
- 数据库代码同时兼容 SQLite / MySQL≥5.7.8 / PostgreSQL≥9.6(扩展库固定 MySQL,测试跑 SQLite)
- 新增配置项必须在 `qianye/config/selfcheck.go` 登记真实消费方
- 前端文案走 i18n,key 放 `web/src/i18n/qy/{en,zh}.json`(**不是** `locales/`,不跑 `i18n:sync`)
- **每条修复/新功能配回归测试,并做回滚验证**(改坏 → 测试变红 → 恢复),报告写实测结果
